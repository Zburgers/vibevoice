# VibeVoice 0.2.8

Version: **0.2.8**. Publication uses the protected `v0.2.8` tag on tested `master` source.

<!-- release-notes:start -->
VibeVoice 0.2.8 makes everyday dictation easier to control and recover, adds verified Whisper component updates, and gives you more control over transcription CPU use.

## New and improved

- **A redesigned floating pill.** See status and your shortcut in a compact capsule, then expand one rounded menu for recording, cancellation, transcript recovery, and opening the app. Long transcripts scroll without hiding the controls. Expansion stays within the monitor work area.
- **A clearer Control page.** Recording controls, elapsed time, keyboard shortcuts, engine readiness, and the last transcript are easier to scan. Navigation adapts to narrower windows.
- **A real microphone frequency display.** Twelve independently measured bands replace the volume-driven animation; the compact pill combines them into six bars. The display does not alter the audio sent to Whisper.
- **Whisper updates inside the app.** Settings and Diagnostics can install the recommended Whisper 1.9.4 engine in the distributed Windows x64 app, with verified downloads, progress, cancellation, and a startup check. No Git, compiler, or CMake is needed. Previous engine files are retained.
- **Default model verification and repair.** Verify the existing base.en English model or download a verified managed copy when needed. This action selects the default English model; updating the engine preserves your selected model. Model repair is available on all supported desktop platforms.
- **Transcription CPU controls.** Choose automatic threading (up to four threads), or a smaller limit to leave more CPU available for other work. Fewer threads may take longer; the model and accuracy settings are unchanged.
- **More useful Diagnostics.** See actual audio length, transcription time, and thread count. Windows also reports Whisper CPU time, average CPU share, and peak memory; these measurements are included in the copyable support report.

## Fixes

- Fixed expanded pill clipping and the rectangular native shadow around its transparent window. Disabled accidental image dragging, text selection, and browser context menus while retaining the move and expand controls.
- Fixed auto-paste when the previous clipboard is empty, with native format/ownership checks on Windows, X11, Wayland, and macOS. Restore supported plain-text or image contents; rich, mixed, and private formats are left untouched with recovery guidance.
- Added a dedicated macOS Command-V adapter with clear Accessibility permission guidance; Diagnostics reports the macOS adapter.
- Auto-paste now works with Clipboard fallback disabled: temporary clipboard staging is separate from clipboard-only output.
- A successful paste remains marked Inserted if restoring the previous clipboard fails. Show a restoration warning and label an intentional repeat as Paste again, avoiding a misleading failed-insertion retry.
- Cancel microphone preparation from Control or the expanded pill without waiting for the microphone to finish opening.
- Keep completed transcripts visible alongside insertion errors, with copy and retry actions so you do not need to record again.
- Prevent saved-transcript copy and retry actions from replacing an active recording or transcription state. These actions wait until the voice session finishes.
- Fixed repeated Stop calls opening a second session during transcription. A cancellation acknowledged before insertion prevents clipboard and paste side effects.
- Finish microphone callbacks before finalizing the recording file, and clean up temporary recordings after preparation failures. Saved duration now reflects recorded audio rather than processing time.
- Bound the microphone-to-disk queue. If storage cannot keep up, fail with an incomplete-audio message instead of accumulating memory or silently transcribing dropped audio.
- Apply the pill's always-on-top setting immediately and restore it on startup. Refresh the pill shortcut as soon as a settings save succeeds.
- Preserve the working global shortcut if a replacement cannot register. Shortcut capture supports punctuation keys and modifier release order, cancels on Escape or focus loss, and suspends the recording shortcut during capture.
- Fixed Windows login startup registration, including executable paths with spaces and rollback when a settings save fails.
- Added Automatic/Custom engine and model choices with native file browsing and validation. Invalid files leave the previous settings intact. Serialize settings saves and report their results.
- Respect the dictionary cleanup toggle and each replacement rule's enabled state.
- Allow healthy slow component downloads to continue, with separate stall and overall time limits. Failed or cancelled verified downloads preserve the previous files.
- Close component cancellation when activation commits, so Cancel cannot report success after the new engine or model is already active.

## Privacy, installation, and packaging

- Automatic engine discovery no longer executes binaries from the launch directory. Project-local engines require an explicit path or configured engine root.
- Use private Unix recording directories and restrict state, history, backups, recovery copies, and exported transcript files to the account owner. The legacy command-line recorder uses a private temporary directory per run and cleans it on exit.
- Update TLS, XML parsing, and error-handling dependencies to patched versions and add a Rust dependency advisory check alongside the existing frontend audit.
- Added Linux app icons and software-center metadata to DEB, RPM, and AppImage packages. Tagged builds finalize the metadata with the actual UTC packaging date.
- Stop the Windows source installer on failed build commands, reject stale installer bundles, quote MSI paths, and check installer results.
- Validate release metadata on every packaging platform. Assemble all signed builds and one complete updater manifest, verify the uploaded draft assets, then publish once with these reviewed notes. A failed build/upload leaves the release unpublished.

## Compatibility and performance

- The distributed Windows app/installer targets x64. The code includes an ARM64 engine package for native development builds, but this release does not distribute or certify a native ARM64 app. Linux and macOS use manual engine setup; default model verification and repair work on all three platforms.
- Auto-paste requires Accessibility permission on macOS, and a compatible keyboard adapter on Linux (wtype, xdotool, or ydotool).
- base.en remains the default model. This release does not claim a universal transcription speedup: lower thread limits trade processing time for CPU headroom, and the measured short-sample engine trials did not establish an upgrade speedup.
- Existing local settings and transcript history remain supported.

## Downloads and upgrading

- **Windows x64:** use the EXE installer or MSI package. Both have matching updater artifacts.
- **Linux x64:** choose the RPM for Fedora/RPM-based systems, DEB for Debian/Ubuntu-based systems, or AppImage. The packages include the application icons and AppStream metadata.
- **macOS Apple Silicon:** use the DMG. The updater uses the matching application archive.
- Existing installations can check for updates in the app once 0.2.8 is the latest release. Fresh Linux/macOS installations still require manual Whisper engine setup. On Windows, use the explicit engine/model actions in Settings or Diagnostics.
