## Confirmed issues fixed during this review

1. **Saved transcript actions could invalidate an active voice session.** `copy_text` changed the voice state to Copied, and retry insertion changed it to Inserted/Error, even during Preparing, Recording, or Processing. That could discard a preparing session, hide an active recorder, or admit another transcription. Both native commands now check under the lifecycle lock before clipboard effects and retain that lock through their state update. Control, Library, and pill recovery buttons are disabled during active sessions. Backend and frontend regressions cover the guard and keep transcription cancellation available.
2. **Component Cancel could acknowledge success after activation.** Activation previously released the lifecycle lock before releasing its busy lease. A waiting Cancel could observe a running update after settings had committed. Component commit now checks cancellation and closes its lease under the same lifecycle lock. Concurrency regressions cover a Cancel waiting on commit, a cancellation acknowledged before activation, and an old lease dropping after a new update begins.
3. **Publication ignored the curated patch notes.** The workflow used a generic release body and generated GitHub notes. It now extracts the reviewed user-facing section of `docs/releases/v0.2.8.md` for every publishing platform; review gates and evidence are kept outside the publication markers. Missing, empty, malformed, or inconsistent notes fail before publication.
4. **Version validation omitted three declarations.** A shared release guard checks package.json, both npm lockfile declarations, Cargo.toml, the VibeVoice Cargo.lock entry, Tauri config, and the frontend fallback version. Tests deliberately change or remove each declaration and reject invalid stable tags.
5. **Error recovery copy misidentified older transcripts.** The Control page no longer describes every new recording/transcription failure as a failed insertion just because an earlier transcript exists. It labels those saved words as the last transcript and keeps the actual error visible.

Windows and macOS now have native test, Clippy, and optimized executable-build CI jobs, alongside the existing Linux Rust/privacy checks and frontend/workflow/script checks. These jobs do not publish assets or require release credentials.

## Independent review remediation (2026-10-04)

PR #77 was independently reviewed at `dd2b61eab6edf975aa74c207f676af2809340f9d`. The seven findings were confirmed against that source and addressed on the same release branch:

| Finding | Remediation and regression evidence |
| --- | --- |
| Windows rich/mixed clipboard loss | Enumerate native formats before choosing text/image; refuse rich, mixed, file and private formats before mutation. The generic snapshot helper also rejects simultaneous text/image payloads. Native text+HTML and text+DIB fixtures assert the clipboard sequence/formats remain unchanged. The native fixture runs only on a disposable Windows CI desktop. |
| Linux empty clipboard rejected | Probe the Wayland offer or X11 selection owner. Empty ownership is distinct from inaccessible/missing protocol; inspect advertised types before restoring a supported payload. An isolated Xvfb test checks empty ownership and unavailable-display failure. |
| macOS paste missing | Dedicated Quartz Command-V adapter checks Accessibility trust, emits balanced key events, releases native events and allows clipboard consumption before restoration. Diagnostics identifies this adapter. Native desktop permission/insertion acceptance remains required. |
| Parallel release publication | Matrix jobs build/sign and retain artifacts only, without release write permission. One dependent publisher validates all three platform receipts/signatures, generates one updater manifest, uploads to a draft, downloads/hashes every asset, and publishes only after the complete set passes. Failure and retry tests verify no publication on build/assembly/upload/digest failure or an existing public release. |
| Auto paste with fallback off always failed | Temporary staging is now driven by paste independently of clipboard-only output. Regression asserts snapshot/copy/paste/restore ordering with fallback disabled. |
| Preparing cancellation inaccessible | Control and expanded pill show enabled Cancel start and invoke stop_recording. Renderer integration tests cover both surfaces. |
| Paste succeeded but restore failed marked Error | Preserve Inserted and report a separate warning. The Control page labels an intentional repeat Paste again. Rust and renderer regressions cover state, warning and recovery labeling. |

Additional review suggestions addressed: callback-to-disk handoff now uses a bounded, nonblocking queue with explicit incomplete-audio failure rather than silent truncation; queue saturation/disconnection tests are included. The CPAL unsafe Send boundary is documented and restricted to Windows/macOS; Linux relies on automatic Send. Platform clipboard, macOS key events and audio-queue behavior have dedicated modules. A pinned Cargo audit gate checks the lockfile for known vulnerabilities.

The Windows distribution claim is narrowed to the x64 app/installer. An ARM64 engine package remains in code for native development builds; this is not a distributed or certified ARM64 app.

The new Cargo audit initially found three vulnerabilities: `RUSTSEC-2026-0194` / `0195` in quick-xml and `RUSTSEC-2026-0285` in rustls. Updated plist to 1.10.1 (quick-xml 0.42.0), wayland-scanner to 0.31.11 (quick-xml 0.41.0), rustls to 0.23.45 / webpki 0.103.15, and anyhow to 1.0.104 to also address `RUSTSEC-2026-0190`. The resulting audit reports zero vulnerabilities, without ignored advisory IDs. Failed and subsequent JSON receipts are retained locally.

Upstream informational warnings remain visible: seven unmaintained dependencies inherited through the desktop stack (`fxhash`, `proc-macro-error`, and five `unic-*` crates), `RUSTSEC-2024-0429` in GTK's glib 0.18.5, and `RUSTSEC-2026-0097` in atomicwrites' rand 0.7.3. These are not a warning-free audit or a security certification. Major GTK/framework migration is outside this bounded release repair; the CI gate continues to print these warnings and rejects vulnerability advisories. No advisories are silently suppressed.

The earlier validation table above describes the pre-remediation candidate and retains its original receipts. Local remediation validation covers 85 passing Windows Rust tests (four explicit native/long probes excluded from the ordinary suite), 38 frontend tests, 14 release/workflow tests, frontend build and strict Clippy. CI explicitly runs the new Windows mixed-clipboard and Linux empty-clipboard native probes; final-head CI results belong to the PR checks rather than the historical table. The prior live Whisper/long-transfer receipts are unchanged; they have not been relabeled as new-head runtime acceptance.

A wholesale coordinator refactor and deletion of older managed engine directories are deferred: they are nonblocking structural suggestions, and preserving previous engines is an intentional rollback promise. Neither changes the seven remediation decisions above. Native graphical acceptance and signed tag-time packaging remain open release gates; mocked publication tests do not publish a release.

- On the final Windows executable, exercise a microphone recording through Stop/transcription/auto-paste into a focused app, including empty/image/text clipboards, failed insertion and recovery, repeat Stop, and cancellation.
- Confirm native shortcut replacement/capture, actual login startup, file pickers, dictionary behavior, pill stacking, and monitor/DPI expansion in the desktop app. Registry/unit/browser checks do not establish these user-visible behaviors.
- Validate current-source Linux packages and graphical installation/software-center metadata, microphone metering/transcription/paste under the target desktop/audio stack, and macOS microphone/privacy/paste/window behavior. Windows ARM64 engine startup is not verified by the x64 probe.
