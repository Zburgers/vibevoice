## Confirmed issues fixed during this review

1. **Saved transcript actions could invalidate an active voice session.** `copy_text` changed the voice state to Copied, and retry insertion changed it to Inserted/Error, even during Preparing, Recording, or Processing. That could discard a preparing session, hide an active recorder, or admit another transcription. Both native commands now check under the lifecycle lock before clipboard effects and retain that lock through their state update. Control, Library, and pill recovery buttons are disabled during active sessions. Backend and frontend regressions cover the guard and keep transcription cancellation available.
2. **Component Cancel could acknowledge success after activation.** Activation previously released the lifecycle lock before releasing its busy lease. A waiting Cancel could observe a running update after settings had committed. Component commit now checks cancellation and closes its lease under the same lifecycle lock. Concurrency regressions cover a Cancel waiting on commit, a cancellation acknowledged before activation, and an old lease dropping after a new update begins.
3. **Publication ignored the curated patch notes.** The workflow used a generic release body and generated GitHub notes. It now extracts the reviewed user-facing section of `docs/releases/v0.2.8.md` for every publishing platform; review gates and evidence are kept outside the publication markers. Missing, empty, malformed, or inconsistent notes fail before publication.
4. **Version validation omitted three declarations.** A shared release guard checks package.json, both npm lockfile declarations, Cargo.toml, the VibeVoice Cargo.lock entry, Tauri config, and the frontend fallback version. Tests deliberately change or remove each declaration and reject invalid stable tags.
5. **Error recovery copy misidentified older transcripts.** The Control page no longer describes every new recording/transcription failure as a failed insertion just because an earlier transcript exists. It labels those saved words as the last transcript and keeps the actual error visible.

Windows and macOS now have native test, Clippy, and optimized executable-build CI jobs, alongside the existing Linux Rust/privacy checks and frontend/workflow/script checks. These jobs do not publish assets or require release credentials.

- On the final Windows executable, exercise a microphone recording through Stop/transcription/auto-paste into a focused app, including empty/image/text clipboards, failed insertion and recovery, repeat Stop, and cancellation.
- Confirm native shortcut replacement/capture, actual login startup, file pickers, dictionary behavior, pill stacking, and monitor/DPI expansion in the desktop app. Registry/unit/browser checks do not establish these user-visible behaviors.
- Validate current-source Linux packages and graphical installation/software-center metadata, microphone metering/transcription/paste under the target desktop/audio stack, and macOS microphone/privacy/paste/window behavior. Windows ARM64 engine startup is not verified by the x64 probe.
